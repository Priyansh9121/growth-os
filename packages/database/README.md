# @growth-os/database

PostgreSQL schema, migrations, connection management, tenant-scoped
transactions, the audit writer and development seed data.

## Why it exists

One place owns the schema, so a migration cannot be authored from three
different mental models — and so swapping the ORM has exactly one blast radius.

## Responsibilities

- The schema (`src/schema/`) as the single source of both types and migrations
- `withTenantTransaction` — the mechanism the isolation backstop depends on
- The redacting audit writer
- Migration and seed scripts
- The integration test harness, including the **restricted role**

## NOT its responsibilities

**Deciding access.** This package _enforces_ isolation; `@growth-os/auth`
_decides_ it. Keeping that split is why `database → auth` is a forbidden edge.

## Dependencies

`@growth-os/contracts`, `drizzle-orm`, `postgres`. Never `auth` or `ui`.

## The two most important lines in this package

**1. `SET LOCAL`, never `SET`.**

```ts
await tx.execute(
  sql`select set_config('app.workspace_id', ${workspaceId}, true)`,
);
```

The `true` makes it transaction-local. A plain `SET` persists for the life of
the _connection_ — and with a pool, that connection goes to the next request,
which would silently inherit the previous tenant's scope.

**2. `set_config`, not interpolation.** `SET LOCAL` does not accept bind
parameters, so a naive implementation concatenates the ID into SQL.
`set_config()` takes real parameters.

## ⚠️ Operational precondition

**The application must not connect to PostgreSQL as a superuser or as the table
owner.** PostgreSQL exempts both from row-level security — `FORCE` closes the
owner hole, but nothing closes the superuser hole. Connect as the restricted
role from `infrastructure/create-app-role.sql`.

The test harness asserts this rather than trusting it, because otherwise every
isolation test would pass vacuously.

## Migrations

Generated by `drizzle-kit`, then **read** before merge, hand-edited where
generation cannot express the intent (RLS policies, partial indexes), and
**immutable once merged**. `drizzle-kit push` is never used outside a throwaway
database — it mutates schema without producing a reviewable artefact.

## Adding a tenant table

Follow the checklist in `docs/security/tenant-isolation.md`. It is not optional.
`audit_events` is the reference implementation.

## Testing

Integration tests against real PostgreSQL, connected as a restricted non-owner
role. Skips itself when `TEST_DATABASE_URL` is unset.
